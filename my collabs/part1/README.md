## Что делает подготовка данных

SCADA-данные записываются регулярно, а журнал отказов содержит отдельные события. Поэтому для разметки используется `pandas.merge_asof`: для каждой SCADA-записи ищется ближайший отказ в окне 10 минут. Если рядом события нет, ставится класс `NF`.

Перед обучением удаляются признаки с утечкой целевой переменной: время, мощность, выработка, часы работы, скорость ветра и служебные поля. Идея такая: модель должна диагностировать состояние по внутренним физическим каналам установки, а не по очевидным последствиям отказа.

## Краткая теория

`SMOTE` создает синтетические объекты миноритарных классов между реальными соседними точками. Это помогает при дисбалансе, но применять SMOTE нужно только внутри `imblearn.pipeline`, чтобы синтетические данные не попали в валидацию заранее.

`BorderlineSMOTE` похож на SMOTE, но больше работает с объектами около границы классов. Он не обязан всегда улучшать результат: если граница шумная, качество может стать хуже.

`LightGBM` — градиентный бустинг над деревьями решений. Он хорошо подходит для табличных данных SCADA, умеет ловить нелинейные зависимости и дает feature importance.

`TimeSeriesSplit` проверяет модель честнее для временных рядов: обучение идет на прошлом, проверка на будущем. Поэтому метрики обычно ниже, чем при случайном `StratifiedKFold`.

`PCA` сжимает многомерные признаки в 2D. Это не замена классификатору, а визуальная проверка: если классы сильно пересекаются в PCA, простого линейного разделения ждать не стоит.
